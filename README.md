# BlockShotsStop (BSS) 0.6

Личное приложение C# / .NET 10 for Android. Проект BSS.csproj, минимальный Android 8, сборка ARM64. Идентификатор org.nikita.shortsguard и локальная подпись сохранены для обновлений.

## Подтверждено пользователем

На Redmi Note 13 / HyperOS / Android 15 версии 0.3–0.4 блокируют короткие ленты YouTube, ВКонтакте и VK Видео. В VK задержка выхода около 2–3 секунд. Интерфейс 0.4 с отступами от системных панелей проверен пользователем. Это не подтверждает другие телефоны, версии приложений или все способы входа.

## Изменения 0.6

1. Исправлено распознавание рекламы по отчёту ВКонтакте 8.201 от 03.11 12:37. Отметка AD_WITH_AGE и кнопка AD_CTA уже распознавались. Ошибка 0.5: ожидался общий контейнер карточки, но VK размещает заголовок, изображение, кнопку и описание отдельными дочерними элементами RecyclerView с ID list.
2. Новое правило связывает рекламный заголовок post_header_profile_container с последующей кнопкой Перейти до следующего заголовка/нижней панели поста. Обычные тексты постов и соседних сообщений не используются для рекламной отметки. Диапазон проверяется на пересечение с видимой областью ленты.
3. Добавлен выбор: чёрная плашка без автопрокрутки либо автоматическая прокрутка. Режим по умолчанию — плашка; общий переключатель скрытия рекламы по умолчанию выключен при чистой установке. Включение из версии 0.5 сохраняется.
4. Добавлен новый значок: бирюзовый щит с перечёркнутым Play на тёмном фоне. Картинка создана встроенным image_gen. Оригинал assets/bss-icon-original.png; краткий промпт assets/icon-prompt.txt. В APK используется адаптивный значок Resources/mipmap-anydpi-v26/ic_launcher.xml.

## Чёрная плашка

TYPE_ACCESSIBILITY_OVERLAY закрывает только найденный диапазон рекламы. Загрузка объявления, его звук и возможные переходы по касанию не блокируются. Плашка не перехватывает касания: можно листать ленту вручную, но нажатие на закрытую рекламную ссылку тоже может пройти в VK.

Пока плашка показана, её положение и активное приложение проверяются каждые 120 мс. При уходе из VK, исчезновении распознанной рекламы, выключении функции или остановке службы плашка убирается. При быстрой прокрутке возможны задержка и визуальное смещение; при переработке интерфейса VK реклама может перестать распознаваться. Плашка закрывает один найденный видимый рекламный диапазон. Режим экспериментальный, на телефоне пока не проверен.

Окно создаётся существующей службой специальных возможностей; разрешение SYSTEM_ALERT_WINDOW не добавляется. Плашка использует экранные координаты и не должна закрывать соседний пост, панель навигации VK или системные кнопки — это нужно проверить на устройстве.

## Автопрокрутка

Вместо плашки выполняется ACTION_SCROLL_FORWARD у ленты. Максимум две попытки с интервалом от 750 мс. Успешная команда вызывает повторную проверку через 900 мс. Новая серия разрешается по событию прокрутки минимум через 1500 мс после последней попытки. Android не гарантирует, что позднее событие вызвано именно ручным жестом. Команда может захватить часть соседнего поста. Счётчик отражает принятые команды, не число скрытых объявлений.

## Проверка на телефоне

1. Установить BSS-0.6.apk поверх предыдущей версии, при необходимости выключить и снова включить службу BlockShotsStop.
2. Убедиться, что служба подключена и общая защита активна. Включить «Скрывать рекламу ВКонтакте».
3. Выбрать «Чёрная плашка без прокрутки». В основном ВКонтакте открыть рекламный пост с отметкой «Реклама · 16+» и кнопкой «Перейти».
4. Проверить границы плашки, ручную прокрутку, возврат к обычному посту и уход в другое приложение. При неверном покрытии выключить скрытие рекламы в BSS. Плашка не должна оставаться поверх других приложений.
5. Проверить второй режим отдельно: «Автоматическая прокрутка».
6. Если не работает: оставить рекламу на экране 5 секунд, перейти в BSS через недавние приложения → Диагностика → ВКонтакте → Копировать. Прислать отчёт и скриншот.
7. Проверить открытие BSS после обновления: на значке должен быть щит вместо стандартного Android. Лаунчер может обновлять кеш значка не сразу.

## Проверки и ограничения

Тесты проверяют старые правила коротких видео, реплеи пользовательских отчётов, рекламные метки, ограничение прокрутки и структуру плоской рекламной карточки из отчёта 12:37. Есть отрицательные проверки: кнопка следующего поста, переход через footer, отсутствие рекламной отметки, другой пакет, точные границы диапазона. Новый реплей сначала воспроизвёл ошибку, после исправления проходит.

Сборка APK и подпись проверяются отдельно. Визуальное покрытие рекламы, пропуск касаний, обновление плашки и её удаление при переходе между приложениями требуют испытания на реальном телефоне. На этой машине ADB-телефон ранее был unauthorized; визуальная проверка через него не выполнялась.

Предыдущие APK и архив исходников до 0.6 сохранены в корне проекта. Не удалять старую установленную версию перед обновлением.

## Данные

Служба наблюдает только com.google.android.youtube, com.vkontakte.android и com.vk.vkvideo. Локально сохраняются настройки, счётчики и последняя структурная диагностика по каждому пакету. Сообщения, названия роликов, скриншоты, звук и видео не сохраняются. Для рекламы в памяти проверяются короткие метки; в отчёт попадают только фиксированные обозначения AD_WITH_AGE/AD/AGE/AD_CTA. Интернет и автоматическое резервное копирование отключены.

## Сборка

```powershell
dotnet build .\BSS.csproj -c Release -p:AndroidSdkDirectory=C:\Users\nikit\AppData\Local\Android\Sdk -p:JavaSdkDirectory="C:\Program Files\Android\openjdk\jdk-21.0.8"
dotnet run --project .\Checks\Checks.csproj
```

Собирать из пути без кириллицы: AAPT2 может не обработать PNG по Unicode-пути. Итоговый файл: bin/Release/net10.0-android36.1/android-arm64/org.nikita.shortsguard-Signed.apk, копия BSS-0.6.apk. Для эмулятора x86_64 нужна отдельная архитектура сборки. PIN и защита от удаления пока не реализованы.

Источники API: https://developer.android.com/reference/android/view/accessibility/AccessibilityNodeInfo и https://developer.android.com/reference/android/view/accessibility/AccessibilityWindowInfo ; отступы UI: https://developer.android.com/develop/ui/views/layout/edge-to-edge
